# Story — творческий конкурс

Веб-приложение для регистрации участников и подачи творческих работ на конкурс.

## Состав проекта

| Каталог | Назначение |
|---|---|
| `Story-Front` | Веб-интерфейс: регистрация, вход, профиль и форма заявки. React + TypeScript. |
| `story-auth` | Регистрация, вход и проверка JWT. Spring Boot, Java 21. |
| `story-common` | Общие сущности, DTO, репозитории, JWT-проверка и MinIO-клиент. |
| `story-back` | Пользовательский API конкурса, заявок и файлов. Spring Boot, Java 21. |
| `story-admin` | Изолированный административный API и Excel-отчёты. Spring Boot, Java 21. |
| `Story-Data` | Docker Compose, PostgreSQL и MinIO. |

Подробная карта каталогов, сервисов и движения запросов находится в
[понятном руководстве по проекту](docs/project-guide.md).
Актуальные ручные запросы находятся в [коллекции Postman](docs/postman/README.md).

## Сборка backend

Для локальной сборки нужны JDK 21 и Maven. Из корня репозитория оба действующих
backend-сервиса собираются и проверяются одной командой:

```powershell
mvn verify
```

Можно проверить только один модуль вместе с его родительским POM:

```powershell
mvn -pl story-auth -am verify
mvn -pl story-back -am verify
mvn -pl story-admin -am verify
```

`Story-Tables` в Maven-сборку не входит. Общие версии Java, Spring Boot, JWT и
плагинов задаются в корневом `pom.xml`; новый backend-модуль следует подключать
к нему как к parent и добавлять в корневой список `modules`.

## Быстрый запуск на Windows

### Требования

- Установленный и запущенный Docker Desktop с Docker Compose.
- Свободные локальные порты `3000`, `5432`, `9000` и `9001`. Порты Java-сервисов
  8000–8002 доступны только внутри Docker-сетей.

### 1. Подготовьте настройки

Откройте PowerShell в корневой папке репозитория. Для локальной разработки
создайте `Story-Data/.env` и заполните случайные секреты безопасной утилитой:

```powershell
.\Story-Data\tools\storyctl.ps1 init-env
```

Утилита генерирует отдельные пароли и JWT-ключ, не печатая их в консоль. Откройте
`Story-Data/.env`. Для localhost задайте `STORY_COOKIE_SECURE=false`,
`STORY_COOKIE_SAME_SITE=Lax` и точный Origin `http://localhost:3000`.

> Не публикуйте `.env` и не используйте локальные настройки в доступной из интернета
> среде. Production-шаблон `Story-Data/.env.example` намеренно не содержит
> секретов и требует HTTPS. Подробности: [безопасная конфигурация](docs/configuration.md).

### 2. Соберите и запустите приложение

```powershell
Set-Location .\Story-Data
docker compose up -d --build
```

Первый запуск может занять несколько минут: Docker скачает образы, выполнит тесты
и соберёт три Java-сервиса, затем соберёт фронтенд.

Для существующей PostgreSQL без истории Flyway сначала выполните безопасную
процедуру baseline из [инструкции по миграциям](docs/database-migrations.md).
Автоматическое изменение таблиц через Hibernate отключено.

### 3. Откройте приложение

| Что | Адрес |
|---|---|
| Веб-приложение | <http://localhost:3000> |
| Gateway health | <http://localhost:3000/gateway/health> |
| PostgreSQL | `localhost:5432` (подключаться через pgAdmin/DBeaver; это не сайт и в браузере не открывается) |
| MinIO API / консоль | `localhost:9000` / <http://localhost:9001> |

Фронтенд перенаправляет авторизацию в `story-auth`, административные запросы и
отчёты — в `story-admin`, остальные API-запросы — в `story-back`. Обычно
достаточно открыть только `http://localhost:3000`.

Прямой доступ с хоста к портам 8000–8002 закрыт. Таблица маршрутов и сетей:
[docs/architecture/api-gateway.md](docs/architecture/api-gateway.md).

Автоматическая проверка, сборка commit-tagged образов и управляемый deploy
описаны в [инструкции Jenkins CI/CD](docs/ci-cd.md). Публикация и production-
развёртывание в pipeline по умолчанию отключены.

### 4. Войдите или зарегистрируйтесь

- Администратор не создаётся автоматически при каждом запуске. Для первого
  создания выполните явную одноразовую bootstrap-команду из
  [инструкции по конфигурации](docs/configuration.md), затем снова отключите флаг.
- Обычный участник регистрируется на главной странице, затем входит с теми же данными. Новые регистрации получают роль `PARTICIPANT`.
- При регистрации укажите корректный email; минимальная длина пароля на сервере — 8 символов.

После входа участник попадает в профиль со списком своих заявок. Ссылки `/profile`, `/application/<contestId>` и `/admin` открываются только согласно роли пользователя.

## Важно: текущее состояние функций

Ссылка восстановления забытого пароля пока не отправляет письмо: для неё нужен
отдельный безопасный процесс с почтовым провайдером (задача T14).

## Остановка, логи и данные

Команды выполняются из каталога `Story-Data`:

```powershell
# Посмотреть состояние контейнеров
docker compose ps

# Смотреть логи всех сервисов
docker compose logs -f

# Логи конкретного сервиса
docker compose logs -f story-back

# Остановить контейнеры, сохранив базу и загруженные файлы
docker compose down

# Удалить контейнеры И ВСЕ данные PostgreSQL/MinIO
docker compose down -v
```

При повторном запуске используйте `docker compose up -d`. После изменений кода пересоберите сервисы командой `docker compose up -d --build`.

> Изменение `STORY_ADMIN_PASSWORD` не меняет пароль уже созданного администратора: он создаётся только при отсутствии записи в базе. Не используйте `docker compose down -v` ради смены пароля — эта команда удалит все данные приложения.

## Локальная разработка

Для разработки frontend с горячей перезагрузкой оставьте контейнерный Nginx как
gateway на порту 3001, а React запустите на 3000:

```powershell
Set-Location .\Story-Data
$env:STORY_FRONTEND_HOST_PORT = '3001'
docker compose up -d --build

Set-Location ..\Story-Front
$env:REACT_APP_API_URL = 'http://localhost:3001/api/v1'
$env:REACT_APP_AUTH_URL = 'http://localhost:3001/api/v1'
npm ci
npm start
```

React откроется на <http://localhost:3000>, а запросы пройдут через gateway на
порту 3001. Прямые порты Java-сервисов останутся закрыты.

`start.bat` проверяет `.env` и безопасно запускает Compose без удаления volumes.
